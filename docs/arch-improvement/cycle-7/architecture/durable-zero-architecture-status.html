AS IS · что действительно есть в коде

Главный entry point уже переведён на новый runner, а composition создаёт реальный PiDurableEngine. Но наличие связей в исходниках не означает успешный запуск всей цепочки.

Проверен ограниченный компонент / пакетКод / перенос в работеОстаточный обход / blockerСуществующая инфраструктура / ещё без нового интеграционного пруфа

Важное различие: зелёный HostBridge с пунктирными связями — готовый отдельный узел, а не работающий host-tool сценарий. Красный rec_… обход условный: default composition передаёт настоящий engine, но Core всё ещё разрешает «принять без исполнения» другим потребителям.

TO BE · один рабочий путь, без обходных успехов

Весь пользовательский поток проходит через настоящий engine. Порты отделяют доменные решения от конкретных SDK, а не подменяют работу «похожими» DTO.

Путь запроса во время работы

Клиент → JSON-RPC → dispatch → coordinator → engine → native Harness → модель / инструмент. Назад — canonical stream и terminal settlement настоящего Submission.

Host-инструмент: engine → внедрённый HostBridge → server.request → клиент → результат → продолжение генерации.

Направление импортов — другое

Runner знает concrete adapters. Адаптер реализует Core-порт. Core знает только доменные контракты; он не импортирует Pi SDK, runner, SQLite или host RPC.

Codemode может импортировать native extension types из adapter-pi-durable; обратная concrete-зависимость запрещена. Runtime dependencies собирает composition.

Pi как провайдер рабочих BB-субтредов и Pi Durable SDK внутри создаваемого продукта — разные уровни. Смена исполнителей на pi не означает замену native движка продукта.

Rule: AP-021 / AP-028 / AP-076; lifecycle and capability preservation

Что защищает от неполной реализации

Walking-skeleton тест не ограничивается accepted: в нём есть text_delta, correlated turn_complete, реальные user/assistant entries и совпадение EntryId после нового процесса. Это правильный тип доказательства — когда он действительно пройдёт.

Стандартный test-script уже включает packages/*/test/*.test.ts, то есть runner-тесты не живут только в чате.

Чего один такой тест не докажет

Он не покрывает всю совместимость, host tools, probe, abort/reuse и отсутствие globals. Его harness пока скрывает stderr и не отклоняет pending request при раннем exit дочернего процесса; таймаут не объясняет причину сбоя.

Успешный esbuild не заменяет typecheck. Нельзя принимать «зелёные старые units» или новый файл за доказательство полного рабочего поведения.

Когда можно будет сказать «не осталось недоделанного целого»

Не гарантия по обещанию, а набор проверяемых условий. Падение любого обязательного сценария блокирует общий PASS, даже если отдельные пакеты зелёные.

  • Реальный ход моделиНе подтверждено

    CLI bin → настоящий Harness; nonce в model output; canonical text_delta; native Submission.wait() завершён с тем же requestId.

  • Durability, не «файл появился»Не подтверждено

    Записи user/assistant читаются через native entries; процесс закрыт; после restart те же EntryId и текст; второй ответ действительно завершён.

  • Нет умных заглушекЕсть открытые места

    Без engine — явная ошибка, не rec_…; метрики из runtime либо explicit unavailable; каждая внедрённая зависимость доходит до реального потребителя.

  • Полнота capabilityОстаётся

    Images-only, root/child, steer/followUp, abort/reuse, abortTask, compact, model/thinking, policy, bindings/fork и история проверяются отдельно.

  • Настоящий host tool round-tripОстаётся

    Модель сама вызывает инструмент; client отвечает reverse RPC; engine использует результат и продолжает генерацию. Один server.request не заменяет этот путь.

  • Изоляция и lifecycleОстаётся

    Два instance не делят host/global state; один владелец session lock; abort/failure/shutdown освобождают ресурсы; probe не открывает сессию.

  • Один собранный кандидатОстаётся

    Чистый build + отдельный typecheck + full tests + AST boundaries; потребитель читает public exports/реальный bin, а не случайный stale dist.

Моя оценка: целевая конструкция соответствует задаче сохранения зрелого runtime. Но сказать «всё уже ок» сейчас было бы неверно. Главный риск — закончить перенос файлов и интерфейсов раньше, чем замкнуть и независимо доказать реальный пользовательский путь. В текущем WIP ещё есть именно те обходы и placeholders, которые такая приёмка обязана не пропустить.
